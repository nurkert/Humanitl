Humanitl @VERSION@ (Vorabversion) - Archiv fuer Linux x86_64
=============================================================

Das ist eine Vorabversion vor dem ersten richtigen Release 0.1.0. Sie ist
nicht fuer den produktiven Einsatz gedacht, nicht signiert und nur mit einer
SHA-256-Pruefsumme versehen. Bevorzugter Weg ist das Paket
humanitl_@VERSION@_amd64.deb aus demselben Release; dieses Archiv ist fuer
Systeme ohne dpkg oder zum Ausprobieren ohne Installation gedacht.


Zum Vergleich: das Paket (.deb)
------------------------------

    sudo apt install ./humanitl_@VERSION@_amd64.deb
    humanitl daemon install
    humanitl daemon status
    humanitl-app

Entfernen, in dieser Reihenfolge:

    humanitl daemon uninstall
    sudo apt purge humanitl

Das Paket richtet den Dienst fuer niemanden von selbst ein. Der Befehl
`humanitl daemon install` aktiviert die Socket-Unit des Pakets
(humanitld.socket); der Daemon startet dann beim ersten Zugriff. Der erste der
beiden Entfernen-Befehle meldet Socket und Dienst wieder ab; das Paket selbst
hinterlaesst nach `apt purge` keine Datei.


Voraussetzungen fuer dieses Archiv
----------------------------------

- Linux x86_64 mit glibc und GTK 3 (zum Beispiel Debian 13 oder Ubuntu 24.04).
- bubblewrap 0.8 oder neuer (Paket `bubblewrap`): ohne `bwrap` startet
  keine Sandbox.
- Unprivilegierte User-Namespaces. Ein frisches Ubuntu 24.04 sperrt sie ueber
  AppArmor (kernel.apparmor_restrict_unprivileged_userns=1); dann scheitert
  jede Sandbox mit der Diagnose SANDBOX_003. `bin/humanitl doctor` prueft
  das und nennt die Abhilfe, `bin/humanitl sandbox check` zeigt, ob die
  Sandbox danach steht.


Pruefsumme
----------

    sha256sum -c SHA256SUMS --ignore-missing


Starten
-------

Im entpackten Verzeichnis humanitl-@VERSION@-linux-x86_64/:

1. Den Daemon als Dienst einrichten und starten:

       ./bin/humanitl daemon install

   Das legt eine systemd-Nutzer-Unit unter ~/.config/systemd/user/ an. Sie
   zeigt auf den Daemon in genau diesem Verzeichnis und startet ihn mit jeder
   Anmeldung. Das gilt fuer ein System ohne installiertes .deb: Ist das Paket
   da, aktiviert derselbe Befehl dessen Units und nicht den Daemon aus diesem
   Archiv. Eine Unit unter ~/.config/systemd/user/, die nicht von
   `humanitl daemon install` stammt, ersetzt der Befehl nie (DAEMON_005); wer
   sie nicht mehr braucht, raeumt sie selbst weg.

2. Pruefen, ob der Daemon antwortet und die Sandbox auf diesem Rechner geht:

       ./bin/humanitl daemon status
       ./bin/humanitl sandbox check

3. Die Anwendung starten:

       ./app/humanitl

Entfernen: zuerst den Dienst abmelden, dann das Verzeichnis loeschen. Wer das
Verzeichnis loescht oder verschiebt, ohne vorher abzumelden, laesst eine Unit
zurueck, die auf einen Daemon zeigt, den es nicht mehr gibt.

    ./bin/humanitl daemon uninstall

Ohne systemd, oder um dem Daemon bei der Fehlersuche zuzusehen, laeuft er auch
im Vordergrund eines Terminals, das offen bleiben muss:

    ./bin/humanitld


Was noch nicht dabei ist
------------------------

- Kein AppImage. Das .deb liegt dem Release bei, dieses Archiv installiert
  nichts.
- Nichts wird automatisch aktiviert. Das .deb installiert humanitld.service
  und humanitld.socket nach /usr/lib/systemd/user/, aktiviert sie aber nicht;
  das tut erst `humanitl daemon install`. Aus dem Archiv schreibt derselbe
  Befehl die Unit selbst. Danach startet der Daemon aus dem Archiv mit jeder
  Anmeldung, der aus dem .deb beim ersten Zugriff ueber den Socket.
- Keine Socket-Aktivierung (humanitld.socket) und kein Menueeintrag im
  Archiv; beides bringt nur das .deb mit. Aus dem Archiv bindet der Daemon
  seinen Socket selbst.
- Die Nutzer-Unit ist so weit gehaertet, wie die Sandbox es zulaesst
  (HUM-053). Einzelne Schutzzeilen fehlen mit Absicht, weil die Sandbox oder
  der Agent in ihr sonst nicht laeuft; welche und warum, steht
  im Abschnitt zur Haertung der Unit in docs/INSTALL.md im Repository
  (https://github.com/nurkert/Humanitl/blob/main/docs/INSTALL.md).
- Keine Signatur. Die Pruefsumme schuetzt vor einem beschaedigten Download,
  nicht vor einem manipulierten Release. Signierte Artefakte kommen mit 0.1.0.
- Keine automatischen Updates; das Programm telefoniert nicht nach Hause.
