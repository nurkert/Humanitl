Humanitl @VERSION@ - archive for Linux x86_64
=============================================

This is an early release on the way to the first full release 0.1.0. It is
not meant for productive use, it is not signed, and it carries only a
SHA-256 checksum; signatures come with 1.0.0. The preferred way is the
package humanitl_@VERSION@_amd64.deb from the same release; this archive is
meant for systems without dpkg or for trying Humanitl without installing it.


For comparison: the package (.deb)
----------------------------------

    sudo apt install ./humanitl_@VERSION@_amd64.deb
    humanitl daemon install
    humanitl daemon status
    humanitl-app

To remove, in this order:

    humanitl daemon uninstall
    sudo apt purge humanitl

The package sets up the service for nobody by itself. The command
`humanitl daemon install` activates the socket unit of the package
(humanitld.socket); the daemon then starts on first access. The first of the
two removal commands unregisters socket and service again; after
`apt purge` the package itself leaves no file behind.


Requirements for this archive
-----------------------------

- Linux x86_64 with glibc and GTK 3 (for example Debian 13 or Ubuntu 24.04).
- bubblewrap 0.8 or newer (package `bubblewrap`): without `bwrap` no
  sandbox starts.
- Unprivileged user namespaces. A fresh Ubuntu 24.04 blocks them through
  AppArmor (kernel.apparmor_restrict_unprivileged_userns=1); every sandbox
  then fails with the diagnostic SANDBOX_003. `bin/humanitl doctor` checks
  this and names the fix, `bin/humanitl sandbox check` shows whether the
  sandbox works afterwards.


Checksum
--------

    sha256sum -c SHA256SUMS --ignore-missing


Starting
--------

In the unpacked directory humanitl-@VERSION@-linux-x86_64/:

1. Set up and start the daemon as a service:

       ./bin/humanitl daemon install

   This writes a systemd user unit under ~/.config/systemd/user/. It points
   at the daemon in exactly this directory and starts it with every login.
   That holds for a system without the .deb installed: if the package is
   there, the same command activates its units and not the daemon from this
   archive. A unit under ~/.config/systemd/user/ that does not come from
   `humanitl daemon install` is never replaced by the command (DAEMON_005);
   whoever no longer needs it removes it themselves.

2. Check that the daemon answers and the sandbox works on this machine:

       ./bin/humanitl daemon status
       ./bin/humanitl sandbox check

3. Start the application:

       ./app/humanitl

To remove: first unregister the service, then delete the directory. Deleting
or moving the directory without unregistering first leaves a unit behind
that points at a daemon that no longer exists.

    ./bin/humanitl daemon uninstall

Without systemd, or to watch the daemon while debugging, it also runs in the
foreground of a terminal that has to stay open:

    ./bin/humanitld


What is not included yet
------------------------

- No AppImage. The .deb is attached to the release; this archive installs
  nothing.
- Nothing is activated automatically. The .deb installs humanitld.service
  and humanitld.socket to /usr/lib/systemd/user/ but does not activate them;
  only `humanitl daemon install` does. From the archive the same command
  writes the unit itself. Afterwards the daemon from the archive starts with
  every login, the one from the .deb on first access through the socket.
- No socket activation (humanitld.socket) and no menu entry in the archive;
  only the .deb brings both. From the archive the daemon binds its socket
  itself.
- The user unit is hardened as far as the sandbox allows (HUM-053). Some
  protection lines are left out on purpose, because otherwise the sandbox or
  the agent inside it does not run; which ones and why is in the section on
  hardening the unit in docs/INSTALL.md in the repository
  (https://github.com/nurkert/Humanitl/blob/main/docs/INSTALL.md).
- No signature. The checksum protects against a damaged download, not
  against a tampered release. Signed artefacts come with 1.0.0.
- No automatic updates; the program does not phone home.
