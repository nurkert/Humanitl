# The contract `humanitl.v1`

Applies to: Humanitl 0.1

> The gRPC proto under `proto/humanitl/v1/` is the only way to talk to the daemon. UI, CLI, tests and later plugins are clients with equal rights (ADR-003, `docs/ARCHITECTURE.md` 1.3 and 3b). Whoever adds a capability adds it here, not next to it.

## 1. The files

| File | Content | Imports |
|---|---|---|
| `proto/humanitl/v1/common.proto` | `Method`, `Scheme`, `Upgrade` | nothing |
| `proto/humanitl/v1/rules.proto` | `Rule`, `RuleMatcher`, `RuleExpiry`, `RuleAction` | `common.proto` |
| `proto/humanitl/v1/humanitl.proto` | Service `Humanitl`, flows, findings, Diagnostics, sandbox, terminal, audit, config, doctor, LLM search | `common.proto`, `rules.proto` |

`common.proto` exists because `RuleMatcher` needs the same methods and schemes as `HttpRequest`. Without the third file there would be an import cycle between `rules.proto` and `humanitl.proto`.

All three files are in the package `humanitl.v1`. For code generation this is a single module; in Rust everything ends up in `humanitl_ipc::v1`.

## 2. Code generation

**Rust** needs neither a script nor a third-party tool. `daemon/crates/ipc/build.rs` compiles the `.proto` files on every `cargo build` with `protox`, a Protobuf compiler in pure Rust, and generates client and server into `OUT_DIR` with `tonic-prost-build`; `src/lib.rs` pulls in the result with `include!(concat!(env!("OUT_DIR"), "/humanitl.v1.rs"))`. Nothing is written into the source tree. A fresh clone builds without `protoc` and without `buf`.

```
make proto          # or: ./scripts/gen-proto.sh
```

does two things: `cargo xtask proto` renews `proto/descriptor.binpb`, and `protoc` with `protoc-gen-dart` generates `app/lib/core/ipc/generated/` together with `proto/generated.sha256`. The compilation itself is written once in `daemon/crates/ipc/proto_gen.rs` and shared by `build.rs` and `xtask` via `include!`, so that Rust code and descriptor never come from different sources.

**Dart** needs `protoc` and `protoc-gen-dart`, the plugin in exactly the version that `scripts/gen-proto.sh` names as `PLUGIN_VERSION` (25.0.0): the hash in `proto/generated.sha256` depends on the plugin's output, and CI compares it with the checked-in state.

```
sudo apt install protobuf-compiler
dart pub global activate protoc_plugin 25.0.0
export PATH="$PATH:$HOME/.pub-cache/bin"
```

If a tool is missing or the plugin version does not match, the script says what to do and exits with 0. With `STRICT=1` or `CI=true` (GitHub Actions sets it) it exits with 1 instead and additionally requires that `proto/generated.sha256` is checked in and that the plugin version can be proven via `dart pub global list`: a `protoc-gen-dart` of unknown origin is an error in strict mode and only a warning at the workstation. That way CI is strict and the workstation lenient. A workstation without `protoc` builds and tests the Rust side completely, but can only run the Flutter gate (`make flutter-analyze`, `make flutter-test`) once `scripts/gen-proto.sh` has generated the Dart code once; `make proto` says what is missing for that.

The version of the Dart plugin (25.x) and that of the package `protobuf` (6.x) belong together. BACKLOG.md and HUM-003 name 22.x/4.x; since then `grpc` 5.x requires the package `protobuf` 6.x, and `protoc_plugin` 25.x goes with that. The plugin is pinned in exactly one place, as `PLUGIN_VERSION` in `scripts/gen-proto.sh`; the CI action `setup-flutter` reads the value from there instead of repeating it (CONVENTIONS.md 4.11: one pin file per tool). The package is pinned in `app/pubspec.yaml`.

## 3. What is checked in and what is not

| Path | In git | Why |
|---|---|---|
| `proto/humanitl/v1/*.proto` | yes | The contract. |
| `proto/descriptor.binpb` | yes | Compiled contract without source positions. Input of `daemon/crates/ipc/tests/proto_contract.rs`, basis for `grpcurl`. Exactly two checks keep it fresh: the test `checked_in_descriptor_matches_the_proto_sources` in the same file compiles the `.proto` files on every `cargo test -p humanitl-ipc` via `proto_gen.rs` (the same code path as `cargo xtask proto`) and compares byte for byte, with the hint `run cargo xtask proto`; and the step "Fail on generated drift" in the CI job `proto-lint-and-gen` (`.github/workflows/ci.yml`) runs `scripts/gen-proto.sh` and aborts if `git diff` afterwards shows anything under `proto/`, `daemon/crates/ipc/` or `app/lib/core/ipc/`. `buf breaking` does not run against it but against the `.proto` files on `main`. After every proto change regenerate with `make proto` (or `cargo xtask proto` in `daemon/`) and commit it along. |
| `proto/generated.sha256` | yes | Hash over the generated Dart files. Only the CI step "Fail on generated drift" keeps it fresh; locally no test checks it, because `generated/` is gitignored and does not come into being without `protoc`. Commit it along after every proto change. |
| `daemon/crates/ipc/src/` | hand-written code only | The generated Rust code lives in `OUT_DIR` under `daemon/target/` and comes into being on every `cargo build`. |
| `app/lib/core/ipc/generated/` | no | Comes into being in `scripts/gen-proto.sh`. Every job that analyses, tests or builds the app generates it first. |

Generated code is not source code (`docs/ARCHITECTURE.md` 4). Whoever changes it by hand loses the change on the next build.

## 4. How to change the contract

1. Additive only, with the one exception in rule 2. New fields get the next free number, new enum values the next free number, new RPCs go at the end of the service.
2. Field numbers are never recycled. A removed field becomes `reserved`, never overwritten. The same applies to enum values. Otherwise a field is removed only with a major bump (section 5), with one exception: a field that demonstrably no handler reads and no client sets. Removing it breaks nobody, because nothing ever depended on it; number and name become `reserved`, and the table below names it (HUM-089). `buf breaking` still reports such a deletion as `FIELD_NO_DELETE`. Independently of that, the step in CI is still set to `continue-on-error`; whoever removes the flag decides that with an ADR, and the same ADR fixes how this exception then stands in the rule set. Neither the flag nor a lower category is a consequence of this exception.

   | Message | Number | Formerly | Why reserved |
   |---|---|---|---|
   | `DecideRequest` | 3 | `allow_edited` as `HttpRequest` | The body travelled only as a `BodyRef`; replaced by `EditedRequest` on 7. |
   | `DecideRequest` | 6 | `acknowledge_findings` as `bool` | Never read, never set; since HUM-160 the acknowledgement stands as `repeated uint32 acknowledged_findings` on 8 (HUM-089). |

3. Every enum has `_UNSPECIFIED = 0` as its first value, and every value carries the name of the enum as a prefix in `SCREAMING_SNAKE_CASE`.
4. IDs are `string` with UUID text, timestamps `google.protobuf.Timestamp`, time spans `google.protobuf.Duration`.
5. Bodies never travel in events. An event carries at most a `BodyRef`; the client fetches the content via `GetBody`. `proto_contract.rs` checks this transitively over everything reachable from `FlowEvent`; a new `bytes` field there must go into the test's allow list, with a reason. A body as content travels in exactly two places, both outside the event stream: in via `DecideRequest.allow_edited` (`EditedRequest.body`, because the daemon has the edited content nowhere else) and out via `GetBody`. In addition there is `FlowDetail.body_preview`, the beginning of the request body as lossy UTF-8 with at most 4096 characters, only in the detail. The test `edited_request_and_body_preview_stay_out_of_the_event_stream` keeps both away from `FlowEvent`.
6. Header values are `bytes`, not `string`. HTTP headers are not guaranteed to be UTF-8.
7. Every variant of `humanitl_core::FlowEvent` has its counterpart in the `oneof event` of `FlowEvent`, so that the mapping is total. An upstream error is `FlowEvent.Failed` with `UpstreamError`, never `ResponseHeaders` with status 502 (CONVENTIONS.md 3.2, 4.10).
8. After the change: `make proto`, commit `proto/descriptor.binpb` and `proto/generated.sha256` along, `cargo test -p humanitl-ipc` and `flutter test`. A forgotten descriptor shows up immediately: `checked_in_descriptor_matches_the_proto_sources` fires as long as `proto/descriptor.binpb` does not match the `.proto` files; a forgotten Dart hash only in CI ("Fail on generated drift"). The tables in `daemon/crates/ipc/tests/proto_contract.rs` are part of the contract and are maintained along with it.
9. A new RPC brings its CLI subcommand along in the same issue (`docs/ARCHITECTURE.md` 3b). The one open exception, `ProbeLlm` (HUM-039), is closed with HUM-114: `humanitl llm test URL` exists, and `humanitl rules test URL` has evaluated via `RulesRequest.Test` since then instead of answering with `CLI_003` (`backlog/CONVENTIONS.md` 4.21). `GetSessionSummary` (HUM-043) brings `humanitl sessions summary <id>` along, `LlmKey` (HUM-140) `humanitl llm key status|set|remove`, `LlmServers` (HUM-289) `humanitl llm server ls|add|use|rename|rm`.

- Additive change ⇒ minor rises. Older clients keep working; they do not see the new fields.
- Removing a demonstrably dead field (section 4, rule 2) is not a break: major and minor stay, because nothing changes for any client.
- Break ⇒ major rises and the package is called `humanitl.v2` in a new directory. `humanitl.v1` stays until nobody asks for it any more.
- A client with a smaller major refuses the connection and shows a `Diagnostic` instead of a half-working interface.

## 6. Lint and compatibility in CI

`proto/buf.yaml` switches on `STANDARD` and excludes five rules, each with a reason in the file: `PACKAGE_VERSION_SUFFIX`, `SERVICE_SUFFIX` (the service is called `Humanitl`, not `HumanitlService`) and the three `RPC_*` naming rules (the request and response names follow BACKLOG.md 3.3, and several RPCs share `google.protobuf.Empty`).

`buf breaking` runs against the `.proto` files on `main` and needs `fetch-depth: 0` in the checkout.

What `buf` checks, the tables in `daemon/crates/ipc/tests/proto_contract.rs` additionally check locally on the checked-in descriptor: `_UNSPECIFIED = 0`, enum prefixes, `snake_case` fields, completeness of messages and RPCs, no bodies in events. That this descriptor reflects the current `.proto` files and not an old state is ensured by `checked_in_descriptor_matches_the_proto_sources` in the same file (section 3). This way a contract violation already shows up in `cargo test`, not only in CI.

## 7. Authentication

Every call carries the session token from `$XDG_RUNTIME_DIR/humanitl/token` (mode 0600) in the metadata header `x-humanitl-token`; the constant for it is `humanitl_ipc::TOKEN_METADATA_KEY`. The transport is a Unix domain socket under `$XDG_RUNTIME_DIR/humanitl/daemon.sock` (mode 0600), not TCP.
